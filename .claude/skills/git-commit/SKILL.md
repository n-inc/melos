# Git Committer

会話コンテキストから変更内容は把握できている前提で、素早くコミットを実行する。
基本的に質問せずステージングからコミットまで一気に完了させる。
どのファイルをコミットすべきか会話コンテキストから判断できない場合のみ確認する。

## 手順

### 1. ステージング & コミット

`git status --porcelain` で状態を確認し、会話コンテキストから今回の変更に該当するファイルを特定して `git add` -> `git commit` を一気に実行する。

- 既にステージング済みならそのままコミット
- 未ステージングなら、会話中で変更したファイルを `git add` してコミット
- 秘密情報ファイル（`.env`, `credentials.json` など）は除外

**コミットメッセージ形式**:

prefix: `feat:` / `fix:` / `refactor:` / `docs:` / `chore:`

- **言語**: 特別な指定がない限り、件名・本文ともに日本語で書く
- prefix や scope などの Conventional Commit 形式は英語のままでよいが、その後の説明文は日本語にする
- **件名**（1行目）: `prefix: 変更内容の要約`
- **本文**（3行目以降）: 以下の構成で「なぜ」を中心に書く
  1. **経緯・背景**: そもそも何をしようとしていたのか、どういう状況だったのか
  2. **問題**: 何が起きていたのか
  3. **原因**: なぜその問題が発生していたのか
  4. **対処**: なぜこのアプローチを選んだのか

コードの差分（何を変えたか）は diff を見れば分かる。本文には diff から読み取れない「なぜそうしたか」を書く。技術的な変更の箇条書きだけにならないよう注意する。

軽微な変更（typo修正、フォーマット等）は件名のみでよい。

```bash
git add file1 file2 && git commit -m "$(cat <<'EOF'
fix: 変更内容の要約

折りたたみサイドバーの開閉時にちらつきが発生していたため、
CollapsedSidebar を条件付きレンダリングから常時マウント方式に
変更していた（前回コミット）。

しかし常時マウントにしたことで、ページ読み込み直後に
CollapsedSidebar 内の useLazyLoadQuery が発火し、Suspense
境界がないまま Promise が throw されて RequireAccountLogin の
エラーバウンダリに到達、ページ全体が白紙になっていた。

CollapsedSidebar を Suspense で囲むことで、データ取得中の
一時停止を吸収するようにした。また isMounted 条件を追加し、
SSR 時の Suspense ハイドレーション不整合も回避した。
EOF
)"
```

コミット完了後、ハッシュとメッセージを簡潔に報告。

### 2. pre-commit フック失敗時

- 自動修正された場合は再ステージして再コミット
- 修正が必要な場合はユーザーに通知

ユーザーから提供されたコンテキスト（引数）がある場合は、それも考慮する。

## 注意事項

### ステージング済み変更のみをコミット

- **staged changes のみ**をコミット対象とする
- ステージングされていない変更がある場合は、事前に `git add` を実行する必要があることをユーザーに通知

### pre-commitフックへの対応

- pre-commitフックが失敗した場合は、エラー内容を確認
- フックによる自動修正があった場合は、修正内容を確認してから再度コミット
- 必要に応じてユーザーに確認を求める

### コミットメッセージの品質

- 既存のコミット履歴（`git log`の結果）を参照し、プロジェクトのコミットメッセージスタイルに合わせる
- 変更内容を正確に反映する（"add"は完全に新しい機能、"update"は既存機能の改善、"fix"はバグ修正など）
- 秘密情報を含む可能性のあるファイル（.env, credentials.jsonなど）はコミットしない
