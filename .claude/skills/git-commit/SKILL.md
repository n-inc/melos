# Git Committer

## 概要

このスキルは、Gitの変更内容を分析し、プロジェクトのコミットメッセージ規約に従った適切なコミットメッセージを生成してコミットを実行する。

このスキルを使用する場面：
- ステージング済みの変更をコミットする
- 適切なコミットメッセージを自動生成したい
- プロジェクトのコミット規約に従ったコミットを作成したい

## 実行手順

### 1. Git状態の確認

以下のコマンドを実行して現在の状態を確認：

```bash
git status --porcelain
git log --oneline -20
git branch --show-current
```

これにより以下の情報を把握：
- 変更されたファイルの一覧
- 直近のコミット履歴とメッセージのパターン
- 現在作業中のブランチ名

### 2. 変更内容の分析

`git diff --staged` でステージング済みの変更内容を確認し、以下を分析：

- **変更の目的**: 何のための変更か（新機能追加、バグ修正、リファクタリングなど）
- **影響範囲**: どのファイル・モジュールが影響を受けるか
- **変更の規模**: 小さな修正か、大きな機能追加か

ユーザーから提供されたコンテキスト（引数）がある場合は、それも考慮する。

### 3. コミットメッセージの生成

プロジェクトのコミットメッセージ規約に従い、以下の形式でメッセージを生成：

#### 基本構造

- **簡潔な要約行**（50文字以内推奨）
  - プレフィックス（feat:, fix:, refactor:, docs:, chore:など）を含める
  - 変更内容を端的に表現

- **詳細説明**（必要な場合のみ）
  - 変更の背景や理由
  - 技術的な詳細

- **影響範囲や補足情報**（必要な場合のみ）
  - Breaking changesの有無
  - 関連するイシュー番号

#### コミットメッセージの例

```
fix: 認証フローの重複コードを統合

LoginFormとSignupFormで重複していた認証ロジックを
auth/utils.tsに集約し、コードの保守性を向上。
```

```
feat: ユーザープロフィール編集機能を追加

ユーザーが自身のプロフィール情報（名前、メールアドレス、
アバター画像）を編集できる機能を実装。
```

### 4. コミットの実行

生成したメッセージで `git commit` を実行：

```bash
git commit -m "$(cat <<'EOF'
コミットメッセージをここに記載
EOF
)"
```

コミット完了後、以下の情報を報告：
- コミットメッセージ
- 変更されたファイルの一覧
- コミットハッシュ
- git status の結果

#### 出力例

```
✅ コミット完了
メッセージ: fix: 認証フローの重複コードを統合

変更ファイル:
- frontend/src/auth/LoginForm.tsx
- frontend/src/auth/utils.ts

コミットハッシュ: a1b2c3d
```

## 注意事項

### ステージング済み変更のみをコミット

- **staged changes のみ**をコミット対象とする
- ステージングされていない変更がある場合は、事前に `git add` を実行する必要があることをユーザーに通知

### pre-commitフックへの対応

- pre-commitフックが失敗した場合は、エラー内容を確認
- フックによる自動修正があった場合は、修正内容を確認してから再度コミット
- 必要に応じてユーザーに確認を求める

### コミットメッセージの品質

- 既存のコミット履歴（`git log`の結果）を参照し、プロジェクトのコミットメッセージスタイルに合わせる
- 変更内容を正確に反映する（"add"は完全に新しい機能、"update"は既存機能の改善、"fix"はバグ修正など）
- 秘密情報を含む可能性のあるファイル（.env, credentials.jsonなど）はコミットしない
